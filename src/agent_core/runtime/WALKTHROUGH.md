# Runtime 模块——完整链路

> 本文件是 `agent_core/runtime` 模块的走读笔记，用图解方式梳理 ReAct 循环全链路。

## 模块文件一览

| 文件 | 干什么 |
|---|---|
| `react.py` | 核心：ReAct 循环（本次重点） |
| `service.py` | 生命周期管理：start/resume/cancel/租约/事件发布 |
| `store.py` | 内存版运行存储（测试/开发用） |
| `compat.py` | 工具函数：消息转 JSON、提取用户输入等 |

## 一句话总结

> **你发一句话 → Agent 调模型 → 模型说"帮我调个工具" → 执行工具 → 结果喂回模型 → 模型说"调下一个工具" → 再执行 → …… → 模型终于说"这是最终答案" → 返回给你。**

这个"调模型→执行工具→回灌→再调模型"的循环，就是 **ReAct 循环**（Reasoning + Acting）。

## 全链路调用图

```
用户发消息 "帮我查上海天气"
         │
         ▼
┌── AgentRuntime.start() ─────────────────────────────┐
│  1. 创建 RunContext（run_id / thread_id / status）    │
│  2. 持久化到 RunStore（SQLite/PostgreSQL）             │
│  3. 发布 run_started 事件                             │
│  4. 启动后台 Task 执行 _execute()                      │
└──────────────────────┬───────────────────────────────┘
                       ▼
┌── ReActAgent.run() ─────────────────────────────────┐
│  调共享内核 _iterate(_RUN_MODE, ...)                  │
└──────────────────────┬───────────────────────────────┘
                       ▼
┌── _iterate() 共享内核 ─────────────────────────────────────────────────┐
│                                                                       │
│  第 0 步：构造初始消息                                                  │
│    messages = [system(角色+规则), user("帮我查上海天气")]                │
│                                                                       │
│  ═══ Agent 主循环（最多 max_iterations=5 轮）═══                        │
│                                                                       │
│  第 1 轮：                                                            │
│  ┌─ ① before_model 中间件 ─────────────────────────────┐              │
│  │   注入防护 / 压缩 / 语义缓存 / 审计 … 28 个中间件检查    │              │
│  └──────────────────────────────────────────────────────┘             │
│                                                                       │
│  ┌─ ② 调 LLM ──────────────────────────────────────────┐              │
│  │   llm.chat(messages, tools=[...])                    │              │
│  │   → 模型返回: "我需要调 get_weather 工具"              │              │
│  │   → tool_calls: [{name:"get_weather", args:{city:"上海"}}] │         │
│  └──────────────────────────────────────────────────────┘             │
│                                                                       │
│  ┌─ ③ after_model 中间件 ──────────────────────────────┐              │
│  │   工具校验 / Self-Check / 成本预算 …                  │              │
│  └──────────────────────────────────────────────────────┘             │
│                                                                       │
│  ┌─ ④ 保存 checkpoint（phase="execute_tools"）──────────┐              │
│  │   万一这时进程挂了，恢复时知道要重执行这些工具           │              │
│  └──────────────────────────────────────────────────────┘              │
│                                                                       │
│  ┌─ ⑤ 执行工具 ─────────────────────────────────────────┐              │
│  │   ToolExecutor.call("get_weather", {city:"上海"})     │              │
│  │   → 返回 tool_message(content="晴 28°C")              │              │
│  │   → 并发策略：多个工具按优先级分批/并行执行               │              │
│  └──────────────────────────────────────────────────────┘             │
│                                                                       │
│  ┌─ ⑥ 保存 checkpoint（phase="model"）──────────────────┐              │
│  │   工具结果已入 messages，下一轮从这里恢复              │              │
│  └──────────────────────────────────────────────────────┘              │
│                                                                       │
│  ┌─ ⑦ 回到循环顶部，messages 现在：                      │              │
│  │   [system, user, assistant(调工具), tool(结果)]       │              │
│  └──────────────────────────────────────────────────────┘              │
│                                                                       │
│  第 2 轮：                                                             │
│  ┌─ ① before_model → ② LLM → ③ after_model ────────────┐              │
│  │   模型看到工具结果，返回纯文本（无 tool_calls）：        │              │
│  │   "上海今天晴，28°C，适合出行。"                       │              │
│  └──────────────────────────────────────────────────────┘             │
│                                                                       │
│  ┌─ ④ 保存 checkpoint（phase="completed"）──────────────┐              │
│  └──────────────────────────────────────────────────────┘             │
│                                                                       │
│  ┌─ ⑤ 没有 tool_calls → break 跳出循环                  │              │

│                                                                       │

                       ▼

│  status → "completed"                                │
│  发布 run_completed 事件                              │
```

## run() 和 stream() 的关系

两个方法**共享同一个内核** `_iterate()`，只是包装方式不同：

| 方法 | 模型调用方式 | 返回 | 用户看到 |
|---|---|---|---|
| `run()` | `llm.chat()` 一次性返回 | `str`（最终答案） | 转圈圈→一次性出结果 |
| `stream()` | `llm.stream_chat()` 逐块返回 | `AsyncIterator[str]` | 打字机效果，边生成边看 |

区别通过 `_LoopMode` 数据类区分（`_RUN_MODE` / `_STREAM_MODE`），内核里所有逻辑写一次，两条路径共用。

## Checkpoint 在循环中的位置

每轮循环保存 **两次** checkpoint：

```
① 模型返回后（有 tool_calls 时）
   phase="execute_tools"     ← 万一这时挂了，恢复时知道要重新执行这些工具

② 工具执行完后
   phase="model"             ← 万一这时挂了，恢复时直接从下一轮 LLM 调用开始
```

恢复时看 `phase` 字段决定从哪里续跑。

## AgentRuntime 生命周期管理

| 能力 | 说明 |
|---|---|
| `start()` | 创建后台 Task，立即返回 `RuntimeRun` 句柄 |
| `resume()` | 从 checkpoint_state 恢复继续跑 |
| `cancel()` | 取消正在跑的任务 |
| 租约（Lease） | 多实例部署时保证只有一个实例跑同一个 run |
| 事件发布 | 每次状态变更把 RunEvent 推给 CallbackManager + EventSink |
| RunExecutor | 可替换执行器（比如 workflow agent 替代 ReActAgent） |

## 关键防线

| 防线 | 作用 |
|---|---|
| `max_iterations=5` | 模型陷入死循环（一直调工具不回答）→ 强制停止 |
| `max_tool_calls=20` | 累计工具调用次数超限 → 报错 |
| `max_repeated_tool_calls=3` | 同一工具同参数调了 3 次 → 死循环守卫 |
| 并行优先级 | 高优先级工具失败 → 低优先级工具被阻断不执行 |
| 流式不可重试 | 文本已经 yield 给前端了 → 不允许 after_model 返回 RETRY |
