# Rerank（重排）：两阶段检索原理与项目设计

> 核心记忆点：rerank 不是"又一个向量检索"，它是**用慢而精的模型，给快而粗的召回结果做最终裁判**——两阶段各取所长，才是 RAG 精度和性能的平衡点。

---

## 一、为什么需要它：两阶段检索范式

检索大量文档时，**精确的模型跑不动全库，快速的模型精度不够**。所以工业界标准做法是两阶段：

```
                       ┌─────────────────────────────────────┐
                       │  知识库（可能 10 万+ 文档）             │
                       └──────────────┬──────────────────────┘
                                      │
              第一阶段：召回（Recall）    │  快、粗，从全库捞回 top-100
                                      ▼
                    ┌─────────────────────────────┐
                    │  向量检索 / BM25              │
                    │  特点：毫秒级，但排序粗糙       │
                    └──────────────┬──────────────┘
                                   │ top-100
              第二阶段：重排（Rerank）  │  慢、精，只对 100 条细排
                                   ▼
                    ┌─────────────────────────────┐
                    │  Cross-Encoder / Rerank API  │
                    │  特点：精度高，但只能小批量      │
                    └──────────────┬──────────────┘
                                   │ top-5
                                   ▼
                          塞进 LLM 上下文
```

## 二、为什么第一阶段"粗糙"、第二阶段"精确"

关键在于两种模型**看问题的方式**：

| 模型 | 架构 | 输入方式 | 优缺点 |
| --- | --- | --- | --- |
| **Bi-Encoder**（embedding 检索） | 查询和文档**各自独立**编码成向量，算余弦距离 | 离线建索引时文档向量已算好，查询时只编码一次 | ⚡ 快（可以 ANN 索引百万级），但查询和文档**没有交互**，语义匹配粗糙 |
| **Cross-Encoder**（rerank） | 查询和文档**拼在一起**送进模型，注意力层让两者充分交互 | 每个文档都要跑一次完整推理 | 🎯 精度高（能理解"这对吗"的深层语义），但慢——对 10 万文档逐对跑不现实 |

**一句话**：Bi-Encoder 是"各自看一眼打个分"，Cross-Encoder 是"放在一起逐字对照打分"。前者快而粗，后者慢而准——所以只能用在缩小后的候选集上。

## 三、Rerank API（不用自己部署模型）

生产上最常见的是调云端 rerank 服务，送进 query + 候选文档，返回相关性排序：

```python
# 典型调用（Cohere / Jina / SiliconFlow 等都有 rerank 接口）
resp = client.rerank(
    model="rerank-v3.5",
    query="低空无人机的禁飞区规定",
    documents=[...top-100 段落...],
    top_n=5,
)
# 返回按相关性重新排序的结果
```

好处：不用部署 Cross-Encoder，成本按调用计费，精度远高于纯向量排序。

## 四、为什么没有它也能跑，有了它质变

**没有 rerank 的典型问题**：向量检索 top-5 里混进了 3 条"字面相似但答非所问"的文档。LLM 拿到这些垃圾上下文：
- 轻则回答跑偏
- 重则被无关内容带偏（间接的 prompt injection 面）

**加了 rerank 后**：Cross-Encoder 把 query 和每个候选段落逐对"精读"，把真正切题的顶上来。**同样的 top-5 名额，装进上下文的文档质量完全不同**——这直接决定 RAG 回答质量。

## 六、面试话术（30 秒版）
